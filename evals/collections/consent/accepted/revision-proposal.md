# 待采纳修订建议

目标：`consent-accepted-rhi-v1` v1 的 `REL_HI`。以下仅为提案，尚未改写 `analysis.json`。

1. **收窄主张 `A_HI`。** 改为：“在 CIFAR-10、ResNet-110 骨架及文中测试的门控与初始化设置中，Identity Mappings 报告的门控变体未优于原捷径。该结果约束门控在该设置下的普适改善解释，不能推出原 Highway 在所有深度、初始化和预算下更差，也不否定它在自身协议中的优化证据。”继续标记 `inferred`。
2. **逐项修正证据支持范围。** `E_I1` 为 `conditional_support`，说明它只支持列出的骨架、数据和设置，不是全称结论，也不能从点估计直接推出显著性；`E_H2` 为 `conditional_support`，只支持原 Highway 所测协议中的优化可行性；`E_H3` 改为 `compatible`，说明它提供输入选择性与评价条件背景，不直接判定统一条件下优劣。
3. **明确关系含义。** `REL_HI` 标签改为“所测残差骨架中的门控边界”；解释写明箭头表达本次综合对过强概括的范围限制，不代表论文作者曾作过该全称承诺，不表示历史影响或已经否定原 Highway 的结论。保持关系 ID 与 `boundary_revision` 类型。
4. **补充必要前提与竞争解释。** 在 `A_HI` 中明确不能跨骨架、宽度、门位置、初始化搜索和预算外推；当前讨论包没有足够信息评价统计显著性。竞争解释保留实现与优化协议差异，不强行归于门控原理。
5. **读取完整报告后同步受影响文字。** 只有采纳后才读取原始 `analysis.json`，定位所有引用 `A_HI` 或 `REL_HI` 的正文和节点，把“条件不同则保留两项结果；条件对齐仍相反则检查实现与随机性”的行动写清楚。不会凭局部包重建未知节点；不添加新论文、来源或未经核查数值。

若采纳，生成同一分析 ID 的 v2，保留 v1 和完整节点/关系映射；执行结构校验与相邻修订校验，再由 JSON 导出新阅读版。采纳者为测试模拟用户，必须在记录中标清，不能记作真实用户或人工质量审核。
